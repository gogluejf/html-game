# Sprite Editor — Plan

Goal: a **sprite editor** that is a superset of the existing sprite viewer
(`.squid-os/sprite-gen/*.viewer.html`). The viewer stays untouched. The editor
is a single self-contained HTML file per project, generated by a small script
that inlines the same `MANIFEST` the viewer uses (built from `state-*.json`).

No skill changes. Just: one generator script + one editor template.

## Deliverables

| File | Purpose |
|---|---|
| `skills/sprite-crop/scripts/render_editor.py` (under `.squid-os/`) | CLI: reads `state-<project>.json`, builds MANIFEST, renders `editor-<project>.html` from template |
| `skills/sprite-crop/templates/editor-template.html` (under `.squid-os/`) | The editor UI/logic with `/*__MANIFEST__*/` placeholder |
| `.squid-os/sprite-gen/editor-petal-panic.html` | Generated output (rerendered) |
| `.squid-os/sprite-gen/editor-abyss-qwen.html` | Generated output (rerendered) |

Usage: `python3 .squid-os/skills/sprite-crop/scripts/render_editor.py petal-panic abyss-qwen`
(default: all `state-*.json` found in the script's parent dir).

## Canvas model (replaces viewer's max-frame box)

- Stage box = **max frame W × 2**, **max frame H × 2** (the "×2" gives room for
  negative offsets and doubles as the default zoom level → requirement 1).
- Origin (0,0) is the **center** of the box; draw an X/Y axis crosshair there.
- Frames are drawn at 2× integer scale, centered on origin, then shifted by the
  frame's `offset {x,y}` (in original pixels).
- All coordinates stored in **original sprite pixels**; rendered ×2.

## Per-entity state (requirement 8: preserved when switching sprites)

In-memory `state[entityName]`:

```js
{
  speed: 8,                    // per-animation fps (req 6)
  playing: true,
  frameIdx: 0,
  collision: {show:true, x,y,w,h},   // shared across ALL frames of the anim (req 4)
  rotation: {show:true, cx,cy},      // shared across frames (req 5)
  frames: [ {                       // per-frame (req 9, 7, 10)
    name, idx,
    crop:{x,y,w,h},                 // read-only display of source crop
    offset:{x:0,y:0},
    scale:{sx:1,sy:1},
    melee:{on:false,x,y,w,h}
  } ]
}
```

Defaults on first selection:
- `collision` = **median** frame size (not mean): compute each frame's
  alpha-bounds bbox, take median w and median h; centered on the median bbox
  center. Handles outliers like tusko_wobble / vine_hound double-sprites.
  Alpha bounds computed once via offscreen canvas per frame (cached).
- `rotation.center` = center of collision box.
- `speed` = 8.

## Tools (toolbar; click selects, second click deselects; only one active at a time)

| Tool | Behavior |
|---|---|
| **Select/Move** (default) | Arrow keys move current frame `offset` ±1px; Ctrl+arrows ±10px. When a frame is selected, draw its offset box (dashed) around the sprite with corner dots (visual only). |
| **Collision Box** | Resizable rect, same for all frames. 8 handles: corners resize both axes, edge-middles resize one axis, **Shift+corner keeps aspect ratio**. Center point is always the box center (dragging body moves the whole box). Show/hide toggle button (separate from tool select). |
| **Melee Box** | Per-frame resizable rect, different color (e.g. orange vs cyan collision). Same 8-handle behavior. Toggle on/off per frame; when off, hidden. |
| **Scale** | 8-handle gizmo around current frame's sprite bounds; dragging resizes `scale.sx/sy` independently (corners do both, edges one axis). Values shown in panel. |
| **Rotation Center** | Click places the pivot; while held, a ghost line/marker follows the cursor so you see final placement before releasing. Show/hide toggle. |

Toolbar semantics (explicit, req "make sure states make sense"):
- Each tool button is tri-state visually: idle / armed / armed+visible.
- Selecting a tool deactivates all others. Re-clicking the active tool
  deactivates it (back to Select/Move).
- Show/hide toggles (collision, melee, rotation) are independent buttons with
  their own on/off styling; they don't arm a tool.
- Play/pause button mirrors spacebar. Frame ◀ ▶ buttons mirror arrows.

## Playback controls (top or bottom bar)

- ⏮ prev frame · ⏯ play/pause (space) · ⏭ next frame
- FPS display + − steppers (per-animation speed, live-updates panel)
- Zoom fixed at 2× (per spec); no other zoom levels for v1.

## Side panel sections

**Animation**
- name (read-only), frame count (read-only)
- speed (fps) number input ←→ synced with −/+ buttons

**Frame** (current frame)
- frame name + index (read-only)
- crop x, y, w, h (read-only, from filename/source metadata if available, else blank)
- offset x, y (number inputs, editable)
- rotation center cx, cy (number inputs, editable)
- scale sx, sy (number inputs, editable)
- meleebox: enable checkbox + x, y, w, h (editable when enabled)

All number inputs two-way bound: drag in canvas updates inputs; typing updates
canvas. Panel updates live during drags.

## Keyboard

| Key | Action |
|---|---|
| Space | play/pause |
| ←/→ | prev/next frame (paused) or step (same as buttons) |
| ↑/↓ | prev/next entity (sidebar nav, like viewer) |
| Arrows (Select tool, frame focused) | offset ±1px |
| Ctrl+Arrows | offset ±10px |
| −/= | speed ∓1 |

(Resolve the arrow-key conflict: arrows drive frame stepping ONLY when the
canvas has focus AND the active tool is not Select-with-offset-drag; simplest
rule: arrows = frame step; offset movement requires holding a modifier? —
Decision: **arrows = frame step; Shift+arrows = offset ±1; Ctrl+arrows =
offset ±10.** This keeps both without ambiguity.)

## Implementation notes

- Single file, vanilla JS, no deps (matches viewer style/theme).
- Reuse viewer CSS palette (#0a0c14 bg, #3ef0ff accent, #ffe23e labels).
- Handle hit-testing in canvas pixel space; convert to sprite space by ÷2.
- Aspect-ratio resize: anchor the opposite corner, scale dx/dy by dominant
  delta.
- Median bbox: sort widths/heights, pick middle (or mean of two middles).
- Generator script: regex-replace `/*__MANIFEST__*/null` with JSON, replace
  title/subtitle strings. ~60 lines Python.

## Validation (mandatory, after implementation)

Once the editor code is written, use the **browser-use** skill to test in a
**visible Chrome** window and validate:

1. Open `editor-petal-panic.html` — sidebar tree renders, first entity auto-selected, canvas shows frame at 2× with axes crosshair.
2. **Side panel correctness** — Animation section shows name/frame count/speed; Frame section shows index, name, crop, offset, rotation center, scale; Melee + Collision sections show values matching canvas boxes. Verify by screenshot.
3. **Tools** — click each tool (SELECT / COLLISION / MELEE / SCALE / PIVOT): verify arming state, second-click deselects back to SELECT, only one armed at a time. Toggle buttons (BOX / M-BOX / PIVOT⁂ / AXES) show/hide their overlays independently.
4. **Collision box** — drag a corner to resize; Shift+corner keeps ratio; edge handles move one axis; body drag moves whole box; panel x/y/w/h update live.
5. **Melee box** — enable via checkbox or clicking with MELEE tool; per-frame only (switch frames → different/absent box); orange color distinct from cyan collision.
6. **Scale** — drag SCALE handles; sx/sy change independently on edges, both on corners; panel updates.
7. **Pivot** — click places marker; drag previews then releases; panel cx/cy update.
8. **Frame offset** — SELECT tool: Shift+arrow ±1px, Ctrl+arrow ±10px; sprite moves, dashed green gizmo follows, panel offset updates.
9. **Playback** — space toggles play/pause (button icon changes), ◀/▶ step frames, −/+ change speed (per-animation: switch entities and confirm speed differs/is preserved).
10. **State preservation** — edit entity A (offset, collision, speed), switch to B, back to A: all edits intact.
11. Screenshot the side panel + canvas at the end as evidence.

Report any failures and fix before declaring done.

## Out of scope (v1)

- Persistence to disk (state lives in memory only, per req 8).
- Multi-select frames, keyframe curves, export of edited state.
- Zoom levels other than 2×.
